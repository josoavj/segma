Démarrage local

Pour utiliser les builds prêts à l’emploi, ouvrez la page GitHub Releases et choisissez le paquet Linux ou Windows correspondant à votre système. Consultez les notes de la release pour le nom du fichier et les consignes d’installation de cette version.

Pour lancer le projet depuis les sources, suivez les étapes ci-dessous. Segma est composé d’une application Flutter et d’un backend Python/FastAPI. Les deux s’exécutent sur le poste de travail ; le backend écoute par défaut sur 127.0.0.1:8000. Aucun hébergement distant ni compte Segma n’est requis.

Prérequis

  • Python 3.10 ou supérieur et pip.
  • Flutter SDK 3.6 ou supérieur.
  • Git et les outils de compilation requis par Flutter pour votre système.
  • Une connexion internet lors du premier téléchargement des poids du modèle.

Installer les dépendances Python

Depuis la racine du dépôt, créez et activez un environnement virtuel :

python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r backend/requirements.txt

Le script d’initialisation peut ensuite effectuer ses vérifications guidées :

bash scripts/init_project.sh

Accès à SAM 3

L’accès aux poids facebook/sam3 peut nécessiter d’accepter les conditions du modèle sur sa page Hugging Face, puis de s’authentifier localement avec Hugging Face CLI :

hf auth login

Cela concerne l’accès au modèle et ne crée pas de compte Segma.

Lancer le backend et l’application

Dans un terminal, activez l’environnement virtuel puis démarrez le serveur :

source .venv/bin/activate
bash scripts/run_server.sh

Dans un autre terminal, à la racine du dépôt :

flutter pub get
flutter run -d linux

Pour Windows, choisissez la cible Windows disponible dans votre installation Flutter. Vérifiez le backend avec :

curl http://127.0.0.1:8000/api/v3/health

Utilisation

  1. Ouvrez un dossier local dans l’explorateur de Segma et sélectionnez une image.
  2. Dans l’éditeur, entrez un prompt décrivant l’objet (SAM 3 donne généralement de meilleurs résultats avec des prompts anglais simples).
  3. Affinez la sélection en ajoutant des clics positifs pour inclure des zones ou négatifs pour les exclure.
  4. Pour un dossier, lancez le traitement par lot : l’application envoie et traite les images une par une, avec progression dans l’interface.

Les extensions acceptées par défaut sont JPG, JPEG, PNG, BMP et WebP. La taille maximale d’un fichier est de 100 Mio. Le backend vérifie que le fichier n’est pas vide et peut être décodé comme image. Le résultat comprend les masques détectés et leurs informations de segmentation.

Conseils pour les prompts et les clics

Un prompt doit nommer clairement le concept recherché. Les termes anglais courts sont généralement un bon point de départ pour SAM 3, par exemple red car, person, yellow flower ou wooden table. Si le résultat est trop large, essayez un terme plus précis ou ajoutez un attribut visuel distinctif.

  • Commencez par un nom d’objet plutôt qu’une longue phrase.
  • Pour plusieurs catégories, essayez une formulation simple telle que cars and trees.
  • Utilisez un clic positif sur l’objet à conserver et des clics négatifs sur les zones à écarter.
  • Les points sont rapportés à la taille de l’image, avec des coordonnées comprises entre 0 et 1. Le backend les convertit en petites boîtes avant de les transmettre au modèle.
  • Réglez le seuil de confiance si l’interface propose ce contrôle : l’API accepte une valeur entre 0 et 1, avec 0,25 par défaut.

La segmentation dépend de l’image, du prompt, du seuil et du modèle. Les clics guident la sélection, mais ne garantissent pas une frontière parfaite.

Configuration

Les paramètres du backend se trouvent dans le fichier .env à la racine du dépôt. Copiez .env.example pour partir des valeurs par défaut :

cp .env.example .env
Variable Valeur par défaut Description
HOST 127.0.0.1 Adresse d’écoute locale du backend
PORT 8000 Port HTTP local
DEVICE cuda Périphérique demandé : CPU, CUDA ou MPS selon la prise en charge
SAM3_MODEL_ID facebook/sam3 Identifiant du modèle
MAX_FILE_SIZE 104857600 Taille maximale d’upload en octets (100 Mio)
UPLOAD_DIR data/uploads Dossier local des images envoyées au backend
OUTPUT_DIR data/masks Dossier local des masques générés
HF_TOKEN aucune Jeton Hugging Face facultatif si l’accès au modèle l’exige

Avec le script fourni, les chemins relatifs sont interprétés depuis le dossier du backend. Ne modifiez le bind réseau que si vous comprenez les conséquences : le mode par défaut limite l’accès au poste local.

API v3

Le backend expose ces routes sur http://127.0.0.1:8000 :

Méthode Route Usage
GET /api/v3/health État du serveur et du modèle
POST /api/v3/upload Envoi d’image multipart avec champ file
POST /api/v3/segment Segmentation par texte ou points
GET /api/v3/model/info Informations du modèle et du périphérique
POST /api/v3/model/change Changement de périphérique ou rechargement

Envoyer une image

curl -F "file=@image.jpg" http://127.0.0.1:8000/api/v3/upload

La réponse contient un nom généré par le serveur. Utilisez cette valeur comme filename lors de la segmentation.

Prompt texte

curl -X POST http://127.0.0.1:8000/api/v3/segment \\
  -H "Content-Type: application/json" \\
  -d '{"filename":"a1b2c3.jpg","prompt":"red car","confidence_threshold":0.25}'

Points d’inclusion et d’exclusion

Les coordonnées x et y sont normalisées de 0 à 1. Le label 1 inclut une zone et 0 l’exclut. Le backend convertit chaque point en petite boîte pour SAM 3.

curl -X POST http://127.0.0.1:8000/api/v3/segment \\
  -H "Content-Type: application/json" \\
  -d '{"filename":"a1b2c3.jpg","points":[{"x":0.52,"y":0.41,"label":1},{"x":0.64,"y":0.49,"label":0}]}'

La réponse fournit notamment la résolution, le nombre d’objets et les informations de chaque objet : libellé, confiance, boîte englobante, chemin du masque et nombre de pixels.

Le traitement par lot est orchestré par l’application Flutter. L’API backend ne fournit pas de route dédiée au traitement par lot.

Résultats et fichiers de masque

Chaque réponse API inclut l’image source, sa résolution, le nombre d’objets, les métadonnées des segments et le dossier de sortie. Pour chaque objet, les métadonnées comprennent un identifiant, un libellé, un score de confiance, une boîte englobante en pixels, le chemin du masque et le nombre de pixels couverts.

Les masques enregistrés en .bin sont des tableaux bruts de valeurs uint8 : un octet par pixel, dans l’ordre des pixels de l’image, largeur et hauteur d’origine. Ce n’est pas un fichier PNG autonome. L’interface Segma lit ces données et dessine une superposition colorée dans l’éditeur.

Architecture

  • Application : Flutter desktop avec gestion d’état Riverpod et client HTTP Dio.
  • Backend : API FastAPI locale, traitement d’image avec PyTorch et SAM 3.
  • Flux : Flutter envoie l’image au backend local, puis lui transmet le prompt ou les points. Les résultats reviennent à l’éditeur.
  • Traitement par lot : l’application répète ce flux pour chaque fichier sélectionné.
  • Données : les uploads et masques sont écrits sous les dossiers de données du backend, modifiables avec UPLOAD_DIR et OUTPUT_DIR.

Le dépôt contient également des guides détaillés : README, référence API, guide des prompts et architecture.

FAQ et dépannage

Le premier démarrage est long

Le backend doit récupérer les poids si nécessaire puis charger le modèle en mémoire. La durée dépend de la connexion, du stockage et de la machine.

Le modèle ne se télécharge pas

Vérifiez l’accès Hugging Face, l’acceptation des conditions de facebook/sam3 et votre authentification CLI si le dépôt du modèle l’exige.

CUDA ou MPS n’est pas proposé

Vérifiez que votre installation de PyTorch correspond à votre système et que le périphérique est disponible. Le CPU reste l’option de repli.

Le backend répond, mais le modèle n’est pas prêt

Consultez la réponse de /api/v3/health et les journaux du terminal du backend pour distinguer l’état du serveur de celui du modèle.

La requête de segmentation est refusée

Il faut fournir au moins un prompt d’au moins deux caractères ou un point. Vérifiez que filename reprend bien le nom renvoyé par la route d’upload, et que chaque coordonnée est comprise entre 0 et 1.

Le fichier est refusé

Vérifiez l’extension JPG, JPEG, PNG, BMP ou WebP, l’intégrité du fichier et sa taille maximale de 100 Mio. Une erreur HTTP 413 indique une taille supérieure à la limite configurée.

L’application n’arrive pas à joindre l’API

Vérifiez que le serveur est lancé sur 127.0.0.1:8000 et consultez les paramètres d’URL du backend dans l’application. L’URL de santé permet de vérifier que l’API répond.
